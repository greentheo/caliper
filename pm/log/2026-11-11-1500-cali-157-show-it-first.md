### 2026-11-11 · CALI-157 (#223) part 2 · Show it first, check it when asked

A first build used to write its goals, plan, author in up to four tries, then run the strength check, the patterns and the score. It now plans (if it's several parts), builds, and shows the part. One automatic repair at most, for a script that doesn't build or pieces that don't account for the solid; anything else is told to the person. The part is on screen as soon as it's written, while the reply is still being put together. Whether it holds, the patterns and the score are there to click, and the card says "not checked yet: check it when it looks right".

Seen in a real browser with a stubbed designer: the part drawn at 8 s with the build still running, and no strength run or patterns. No live call. The clarifying questions before the build are unchanged. The whole suite is CI's.

Rework after the review: when the part shown still has pieces that don't match after its one repair, the reply says so first. The goals job asks Claude with no lock on the design and only writes under it, so a correction or Check it holds never waits behind it. The `construction_volume` repair and the page's redraw on "wrote" are pinned by behaviour; the dead code is gone.
