### 2026-11-11 · CALI-89 (#65) · The chat sends each message where it was meant to go

Five kinds of message went to the wrong place, and two of them started an authoring run, which revises a part and costs an API call:
- **A change inside an explain-request** ("I don't get it, make it 2 inches taller") used to read as a question, and the change was dropped. An explain phrase now makes a message a question only when it asks for nothing else.
- **"Say it simpler" typed** used to start a refine. Simpler or plainer words with no change in them ("simpler please", "in plain English", "explain like I'm five") are now questions.
- **"Make it look like a dinosaur"** used to become a new part. It's now a question, answered with the picture offered: "Say 'put a dinosaur on the side'… Nothing's changed."
- **"Add a dino skid on the bottom"** used to cut a T-rex into the front. A … skid, foot, leg or shelf is a part, not a picture.
- **"Make it 2 in wider"** with nothing selected used to start a new part named "part". On a one-part design, a change goes to that part. "Add a shelf" is still a new part.

Claude's router has the same rules. A table test runs every message in the issue, scoped and not, offline. The whole suite is CI's.
