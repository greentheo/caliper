# CALI-231 (#371's page part): a plan's open question is said above Build it

— night shift (UI lane), 2026-11-21

**Why:** #371 (CALI-218) keeps the question about a part named for what a design stands on (`box_floor`, neither fixed
nor made) with the plan. Build it builds nothing while it's open: it only replies with the question. The page showed a live
Build it with no question beside it, and the What is it? card said "Say what to change, or press Build it."

**What's built:**
- **Server:** `design_api._plan` carries `questions`.
- **Page:** `asksHtml` says each question as "Before I build it: …", amber, escaped. It's shown above the chat's
  Build it and at the top of the plan's section. While a question is open, Build it is disabled, and its note reads
  "say it below, and I'll change the plan".
- **The What is it? card (answers.design):**
  - with a question open, it says "Answer its question first: Build it waits for it", then each question, never
    "press Build it";
  - with no key, it says what it said before.

**Judgment calls:**
- **Build it is disabled, not live.** Pressed, it builds nothing and repeats the question that's already above it.
- **The card's line is in answers.py.** It's one line beside the page change, and it would contradict the disabled
  button otherwise.

**Walked** on 8021 with a scratch design whose plan asks about its box floor (`designs/step-stool`):
- the plan section said the question;
- with a dummy key, pointed at a closed local port so no call could leave the machine, the chat said the question
  above a disabled Build it;
- the launch entry went back to no key after.
- Screenshots: `pm/demo/2026-11-21-plan-asks/`.

**Tests:** `tests/test_plan_asks.py`, 7 (fail on main).

**Mutants (8/8 caught):** no `questions` field; not disabled; not in the chat; not in the plan's section; unescaped;
below the button; the card says "press Build it" over a question; the card leaves the question out.

**Round 2 (reviewer-3's must-fix).**
- **The bug:** answered in the chat, Build it came back, but What is it? kept saying "Answer its question first". The
  cards' key (`answersKey`) had no plan in it, so an edit to the plan never asked for the cards again.
- **The fix:** it carries the plan's status, its parts' ids and its questions.
- **Pinned:** answered, a part dropped, and saved each ask again; no plan does too.
- **Mutants (2/2 caught):** the key as it was; the key without the questions.
