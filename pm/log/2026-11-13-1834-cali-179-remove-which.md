### 2026-11-13 · CALI-179 (#287) · "Remove X" never goes to the designer; one part's revision that moved nothing has no ✓

A P1 from Theo's live session on step-stool-5, filed by the foreman. He typed "remove the inside_ inside_corner_fillets", a typo, with the part selected. `_named_part` takes an exact id only, so the message fell through to the designer. That wrote v4 with nothing changed, and the reply opened "✓ revised inside_corner_fillets". An earlier "… remove this part" did the same.

- **A remove names its part closely (`chat._remove_target`).** It resolves:
  - the exact id, or the id with spaces, as before;
  - the id's words in any order, or an underscore astray ("inside_ inside_corner_fillets", "fillets_corner_inside");
  - one letter added, dropped or changed, on an id of 8 letters or more ("inside_corner_filets", "inside corner fillet");
  - where several parts are close, the selected one.

  Then it asks once, as before: "Remove inside_corner_fillets? Its files go to the design's trash, so it can be put back."
- **"Remove which part?"** Words that look like a part's name, with an underscore or ending "part", but name none get "Remove which part? step_stool, inside_corner_fillets". A part's name answers it, and the turn then asks to remove that part.
  - **A feature still goes to the designer:** "remove the fillet on the top" or "remove the holes" has no underscore and names no part, so it's an edit as ever (#98's test still holds).
- **Mid-sentence:** "… superseded: remove this part" on a selected part asks to remove it. With nothing selected, it isn't taken.
- **The page's context is stripped before every intent match (`chat.bare`).** Theo's answer to "Remove inside_corner_fillets?" reached the server as "About the inside corner fillet strip (superseded: step_stool now prints these itself; delete this part from the design): remove it". The page puts the selected piece's or pick's chip text first, so the parked question went unanswered, the anchored `_REMOVE` missed, and the designer revised the part again (v5, ✓).
  - **What every intent match now reads:** the typed words. They're a pick's own text (a joint's chip has a colon of its own), or what follows "About the …:" / "About this …:" while a part is selected.
  - **Skipped as part of the prefix:** brackets in a piece's name, with a colon inside them.
  - **Where it's used:** the yes/no answers, remove and restore, the mirror wording, the "?" checks, the routing and the goal words. `chat.turn` is the only place that reads the message.
  - **Still the whole message:** the designer and the answers, since it says which piece; and the grain, which reads the piece's name from it.
  - **Typed by hand with nothing selected,** "About the top: …" stays as it is.
- **A parked "Remove it?" is answered** by "yes", "remove it" or the part's name with that part selected. A remove that names another part asks about that one instead.
- **Rule 6 on the one-part path:** #242's rule reached only the several-parts path. Now a single part's revision where no number, volume, box or centre of mass moved opens "! revised **inside_corner_fillets** → v2 …: the code changed, but no number, size or position I measure moved", and isn't a success. It's still written, so nothing's lost.
  - **A joint or pick that measured as landed keeps its ✓:** a rabbet is the same solid.
  - **`refine_part` measures `moved` on every path now,** not only when it's one of several parts.
